# PVZ 经验值系统——开发技术手册

> 本文档记录了为原版 PVZ (1.0.0.1051) 添加植物实时经验值显示系统的完整技术细节。
> 新对话加载此文件即可跳过全部摸索阶段。

## 一、项目结构

```
pvzclass/
├── pvzmain/          # 控制台注入器（注册事件 hook + 注入 DLL）
│   └── pvzmain.cpp   
├── pvzdll/           # DLL（在游戏进程内运行）
│   ├── pch.cpp       # 核心逻辑（init, 绘制, 事件处理）
│   └── pch.h         # DLL 导出函数声明
├── pvzclass/         # PVZClass 库
│   ├── PVZ.h         # 游戏数据结构定义
│   ├── Draw.h/cpp    # 绘制封装（我们不用这个——它有 bug）
│   └── Events/       # 事件 hook 类
└── build.bat         # 一键编译脚本
```

## 二、运行流程

```
build.bat 编译 → 启动游戏(主菜单) → 运行 pvzmain.exe → 进入关卡
```

pvzmain 负责：注入 DLL → 调用 DLL init() → 注册所有事件 hook
DLL 负责：绘制经验值数字 + 处理经验增减事件

## 三、关键技术参数（仅限 1.0.0.1051 原版）

### 游戏版本检测
```cpp
// 版本特征值在 0x552013，必须为 0xC35EDB74
int ver = PVZ::Memory::ReadMemory<int>(0x552013);
```

### 绘制 hook 点
| 项目 | 值 |
|---|---|
| Hook 地址 | **0x417DA0**（不是 0x41ACDF！） |
| 原代码 | `push -01; push 0x0064807D`（7 字节） |
| 入口寄存器 | **EDI = gridItem**（渲染上下文，有颜色/字体字段） |

### gridItem 颜色字段
```
[edi+0x30] = R (BYTE)
[edi+0x34] = G (BYTE)
[edi+0x38] = B (BYTE)
[edi+0x3C] = A (BYTE)
[edi+0x40] = font (DWORD, 从 [0x6A75C8] 加载)
```

### 游戏原生绘制函数
| 函数 | 地址 | 调用方式 |
|---|---|---|
| SetString | 0x404330 | `__thiscall`, ECX=this(0x72abf5), push len, push str, **callee 清栈** |
| DrawText | 0x587120 | push y, push x, push string(0x72abf5), **EAX=graphics(gridItem)** |

### 关键游戏地址
```
0x6A9EC0   → PVZ_BASE (LawnApp 指针)
PVZ_BASE + 0x768 → Board 地址
0x6A75C8   → 字体属性（全局）
0x72abf5   → 游戏 SexyString 缓冲区（用于 SetString 写入后传给 DrawText）
```

### 植物数据读取
**正确方式：用 `PVZ::Board::GetAllPlants()`，不要手工遍历 DataArray！**

```cpp
PVZ::Board board(boardAddress);
auto plants = board.GetAllPlants();
for (auto& plant : plants) {
    int row = plant.Row;          // 行 (0-5)
    int col = plant.Column;       // 列 (0-8)
    int plantAddress = plant.GetBaseAddress();
    // 像素坐标换算
    int px = 25 + col * 80;
    int py = 165 + row * 100;
}
```

## 四、DrawText 调用的标准模板

```cpp
// 步骤1: 把数字字符串写入 game buffer
char numStr[16];
sprintf_s(numStr, "%d", exp);
PVZ::Memory::WriteArray<char>(g_stringBuffer, numStr, strlen(numStr) + 1);

// 步骤2: 用游戏 SetString 拷贝到 SexyString 对象
__asm {
    pushad
    push len
    push g_stringBuffer
    mov ecx, 0x72abf5       // this = SexyString 对象
    mov eax, 0x404330
    call eax
    popad
}

// 步骤3: 用游戏 DrawText 绘制（EAX 必须传 gridItem！）
__asm {
    pushad
    push y
    push x
    push 0x72abf5
    mov eax, gridItem       // ★ 第4参数(graphics)在 EAX，不是栈！
    mov ebx, 0x587120
    call ebx
    popad
}
```

**关键：每个调用段都包 `pushad/popad`**——既保护寄存器，又自动清理栈（不用管 callee 是否清栈）。

> ⚠ **2026-10-20 重要更新：不要再拿这个模板画 mod UI 文字。**
> 中文版 4 个字体全局（0x6A7384/0x6A74B0/0x6A75C8/0x6A7714）运行时 vtable 都是
> 0x672614，`vtable+0x28 → +0x34 → SysFont::DrawString(0x599EC0)`，最终是
> **GDI SelectObject + TextOutA**；DC 是按 surface 全局缓存的（0x56C720→[surface+0x70]），
> 横幅/动画/钱币等先画过的状态会残留 → 字号忽大忽小、颜色变黑/绿。
> 克隆 Graphics 也复制不了 surface DC。
>
> 经验值/Lv 数字现在改走 `NativeDrawExpGlyphs`：与**阳光/钱币/卡片价格同款字体**
> **`FONT_CONTINUUMBOLD14`（0x6A7384）= Arial Unicode MS 14pt Bold** 离线
> `TextOutA` 渲染成 `assets/expfontcoin14/ExpFontGDI_*.png`，运行时 `Draw::DrawImage(0x587150)`
> 逐字绘制；`advance/dx/dy` 与原版 GDI 一致，黑色 +1,+1 投影，完全绕开 DrawString/GDI/DC。
> 中文路线文字继续用 PNG 贴图。
> 详见 `经验值文字绘制修复说明.md` 与 `.workbuddy/memory/2026-10-20.md`。

## 五、常见坑（★★★ 每次写 hook 代码前必读）

### 1. DEP + 堆内存不可执行
DLL 内用 `PVZ::Memory::AllocMemory` 分配的是 `new BYTE[]`，DEP 下不可执行。
**打 hook 的 trampoline 必须用 `VirtualAlloc(NULL, size, MEM_COMMIT, PAGE_EXECUTE_READWRITE)`**

### 2. DrawText 第4参数在 EAX
`0x587120` 需要 `graphics` 对象在 EAX 寄存器，不是栈上。PVZClass 的 `Draw::DrawString` 用 `MOV_EAX(graphics)` 传参，但它的 `INVOKE` 宏破坏了 EAX。
**直接从 `__asm` 块传 `gridItem` 到 EAX**

### 3. 版本必须匹配
PVZClass 只完全支持 1.0.0.1051 (0xC35EDB74)。其他版本所有 hook 地址全错。

### 4. 不要用 Draw 类
`Draw::SetColor`/`Draw::FillRect`/`Draw::DrawString` 依赖正确的 graphics 参数且通过 Execute 间接调用——在 0x41ACDF hook 点有根本问题。直接用游戏原生函数。

### 5. Hook 点选择
- 0x41ACDF (DrawUITop): 没有正确的 graphics → 废弃
- 0x417DA0 (griditem 绘制循环): EDI=gridItem，直接写颜色 → **正确**

### 6. DataArray 是结构体数组，不是指针数组
DataArray 的 stride = `0x14C` (Plant::MemSize)，不是 `sizeof(int*)`。
**永远用 `PVZ::Board::GetAllPlants()` 遍历植物，不要手工遍 DataArray！**
手工 `plantArray + i * 4` 读到垃圾数据 → 空指针崩溃（已复现：i=2 时读到 0x78 崩溃）。

### 7. Plant::MemSize = 0x14C，不是 Zombie 的 0x15C

### 8. ★★★ DLLEventTemplate hook 函数三大铁律 ★★★
`DLLEventTemplate` 生成的 trampoline **不保护寄存器**（与手写 trampoline 不同）。

**铁律 A：函数体首尾必须 PUSHAD / POPAD**
```cpp
void hookFunc(DWORD param) {
    __asm pushad       // ★ 第一行
    // ... 所有逻辑 ...
    __asm popad        // ★ 最后一行
}
```
违规症状：函数内代码全部执行成功（弹窗调试全部通过），函数返回后游戏崩溃。
已验证崩溃：铲除植物后 `onPlantRemove` 全部 9 个调试弹窗通过，返回后崩于 `0x57F51E83`。

**铁律 B：PUSHAD/POPAD 块内禁止写全局变量**
违规症状：与 A 相同——函数内执行成功，返回后崩溃。原因不明但稳定复现。
**解决方案**：写入栈上局部变量，`popad` 之后再赋值给全局变量。
```cpp
__asm pushad
saveRow = row;     // 写局部变量 ✅
__asm popad
g_lastDeathRow = saveRow;  // popad 之后写全局变量 ✅
```

**铁律 C：PUSHAD/POPAD 块内禁止调用 PVZ::Memory::ReadMemory**
违规症状：与 A 相同。原因不明但稳定复现（即便 `localExecute=true` 时它只是 `*(T*)addr`）。
**解决方案**：改用纯 `__asm` 内联汇编读内存。
```cpp
// ❌ 崩溃
int row = PVZ::Memory::ReadMemory<int>(plantAddress + 0x1C);

// ✅ 安全
int row;
__asm { mov eax, plantAddress; mov eax, [eax + 0x1C]; mov row, eax }
```

### 9. ★ 选择安全的 hook 点执行重量级操作
- `PlantDieEvent(0x4679B9)`：植物移除中途，**禁止遍历植物数组**。
- `UpdateGameObjectsEvent(0x4130D0)`：先于游戏本体更新，**时机不安全**（已复现：`DistributeRowExperience` 在此崩溃）。
- **`0x417DA0` 绘制 hook**：渲染阶段，游戏状态完全稳定，**所有重量级操作放在这里** ✅。

### 10. UpdateGameObjectsEvent 需要手动注册
`pvzmain.cpp` 不会自动注册，必须显式创建 `UpdateGameObjectsEvent` 对象。

### 9. UpdateGameObjectsEvent 需要手动注册
`pvzmain.cpp` 中不会自动注册此类事件。必须显式创建 `UpdateGameObjectsEvent` 对象并调用 `end()`。

## 七、完整架构流程图

```
pvzmain.exe 启动
  ├─ ProcessOpener::Open() 找游戏进程
  ├─ PVZ::InitPVZ(pid) 连接
  ├─ InjectDll("pvzdll.dll") 注入
  ├─ InvokeDllProc("init")
  │   ├─ localExecute = true
  │   ├─ 读取配置
  │   ├─ 在 0x417DA0 打 trampoline hook ← onDrawExpUI
  │   └─ 弹窗确认
  ├─ DrawUITopEvent (0x41ACDF) 注册 → stub onDrawUITop
  ├─ PlantCreateEvent → onPlantCreate → g_plantExperience[addr]=0
  ├─ PlantDieEvent → onPlantRemove → 读经验+行号 → popad后写g_lastDeathRow/Exp → 清除记录
  ├─ onDrawExpUI(0x417DA0 hook) → 检查g_lastDeathRow → DistributeRowExperience → 清标志
  ├─ ZombieRemoveEvent → onZombieRemove → 查找击杀植物并加经验
  ├─ PlantAddProjectileEvent → onPlantAddProjectile → g_projectileShooterMap
  ├─ ProjectileHitZombieEvent → onProjectileHitZombie → 记录击杀关系
  └─ system("pause") 等待退出
```

## 八、死亡经验转移崩溃调试实录

> 2026-07-26，铲除植物崩溃，经过约 13 轮修改 + 编译 + 测试 + 弹窗定位，最终修复。记录如下供后续参考。

### 崩溃版本迭代

| 轮次 | 方案 | 结果 | 诊断 |
|------|------|------|------|
| 1 | onPlantRemove 中直接调 DistributeRowExperience | 崩 | 怀疑遍历植物数组不安全 |
| 2 | 延迟到 onGameObjectsUpdate | 崩（9个调试弹窗全部通过，返回后崩） | 寄存器污染 |
| 3 | +PUSHAD/POPAD 包裹 | 崩 | 不是寄存器问题 |
| 4 | 回归测试：仅 RemovePlantExperience（版本A） | ✅ | 基线确认 |
| 5 | A + PUSHAD/POPAD（版本B） | ✅ | pushad 本身安全 |
| 6 | B + find + ReadMemory（版本C） | 崩（返回后） | 怀疑 ReadMemory |
| 7 | B + find + 纯 asm 读行号（版本F） | ✅ | 确认 ReadMemory 有问题 |
| 8 | F + 写全局变量 | 崩（返回后） | 全局变量写入也有问题 |
| 9 | F + 写局部变量，popad 后写全局 | 崩（返回后） | ??? |
| 10 | 怀疑是 onGameObjectsUpdate 崩 | 每帧弹窗阻塞游戏 | 事件确实触发 |
| 11 | onGameObjectsUpdate 中调 DistributeRowExperience | 崩在 DRE 调用前 | UpdateGameObjectsEvent 时机不安全 |
| 12 | 改到 onDrawExpUI（绘制 hook）处理 | 崩在 DistributeRowExperience 内部 | DistributeRowExperience 自身 bug |
| 13 | DistributeRowExperience 加弹窗 | DRE-5: i=2, addr=0x78 崩 | **DataArray 被当指针数组遍历** |
| 14 | 改用 GetAllPlants() | ✅ | **修复成功** |

### 最终确立的铁律（写入"常见坑"第 6-9 条）

1. **DataArray 是结构体数组（stride=0x14C），必须用 GetAllPlants()**
2. **DLLEventTemplate hook 函数必须 PUSHAD/POPAD**
3. **PUSHAD 块内禁写全局变量 → 用局部变量桥接**
4. **PUSHAD 块内禁调 ReadMemory → 用纯 asm**
5. **重量级操作放在 0x417DA0 绘制 hook，不要放 PlantDieEvent 或 UpdateGameObjectsEvent**
  ├─ ZombieRemoveEvent → onZombieRemove → 查找击杀植物并加经验
  ├─ PlantAddProjectileEvent → onPlantAddProjectile → g_projectileShooterMap
  ├─ ProjectileHitZombieEvent → onProjectileHitZombie → 记录击杀关系
  └─ system("pause") 等待退出
```
