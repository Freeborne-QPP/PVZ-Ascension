# 经验值文字 / 升级路线文字绘制异常——修复说明（2026-10-20）

## 1. 现象回顾

- 植物右下角的 `Lv.X` 与经验数字颜色不稳定：有时正常，有时变黑/发绿；只有左下角钱币计数器也在绘制时才正常。
- 西瓜投手"选择升级路线"窗口里的「方案A / 方案B」「A：极致的输出 / B：强大的群控」字号会突然变大/变小；
  横幅存在时一个字号，横幅消失后另一个字号。
- 2026-09-08 的结论：根因在游戏文字渲染的**共享 surface DC / 字体对象状态**，当时用
  "强制钱币计数器每帧绘制"把经验文字颜色**意外**修好；路线文字始终没修好，最后改成 PNG 贴图。

## 2. 真正的根因（本轮整理）

游戏 `Graphics::DrawString`（`0x587120`）只是转发：

```
Graphics::DrawString(x, y, PString, Graphics*)
  -> [Graphics+0x40] = Font*
  -> Font->vtable[0x28](Graphics*, x, y, PString*, Color*, ClipRect*)
```

中文版实际使用的 4 个字体全局（`0x6A7384/0x6A74B0/0x6A75C8/0x6A7714`）运行时
vtable 全是 `0x672614`，`vtable[0x28] = 0x58EAB0` → `vtable[0x34] = 0x58E290`
→ `SysFont::DrawString (0x599EC0)` → **GDI `SelectObject` + `TextOutA`**。
也就是说 `.txt`/字形图集仍用于字宽等度量，但**绘制全部走 GDI**：

| 文本 | 实际路径 | 依赖的状态 |
|---|---|---|
| ASCII（`Lv.5`、经验数字） | `Font->vtable[0x28]` → `[0x34]` → `SysFont` GDI | **按 surface 全局缓存的 DC** |
| 中文（`方案A`、`A：极致的输出`） | 同上（GDI） | 同上 |

`SysFont` 的 DC 是 `0x56C720 -> [surface+0x70]` 的全局缓存，绘制函数**只设置自己需要的
几项，不保存/恢复**。任何先画过的 UI（横幅滑入、缩放动画、钱币计数器等）都会把状态
残留在同一个 DC 上，于是：

- 颜色被别的绘制覆盖 → 经验文字变黑/绿；
- 世界变换/映射模式被横幅动画残留 → 字号忽大忽小（中英文都可能）；
- 复制 `Graphics` 只能复制 `+0x00..+0x48` 的字段，**复制不了 surface 上的 DC**，所以
  "克隆 Graphics + 重新 SetFont/SetColor" 对字号无效（这正是 9 月那轮 probe 的结论）。

结论：**不要在共享 DC 上画 mod 文字**。所有需要稳定字号/颜色的文字都应该绕开
`DrawString` 的 GDI 路径（字形图、贴图、或私有 DIB 渲染）。

## 3. 本轮修复方案

### 3.1 经验值文字：用阳光/钱币同款字体生成字形图（不再调用 DrawString）

阳光数量、钱币数量、卡片价格用的是 **`FONT_CONTINUUMBOLD14`**（`0x6A7384`），
中文版 SysFont 实际是 **`Arial Unicode MS` + Bold（14pt）**。这就是用户要的"原字体"：
粗体、紧凑，不像 HouseofTerror/普通 Arial 那样细。

用同一个 GDI 字体（`CreateFont("Arial Unicode MS", 14pt, Bold)` + `TextOutA`）
离线渲染 `0-9 L v .`：

- 黑底白字 → 转成 **白字 + alpha** 的 RGBA PNG（alpha = 原图亮度）；
- 每个字形裁到实际墨迹 bbox，记录：
  - `advance` = `GetTextExtentPoint32A` 的字宽（与原版 GDI 完全一致）；
  - `dx/dy` = 墨迹左/上边界相对 `TextOutA(x,y)` 原点的偏移（与 GDI 完全一致）；
- 运行时用 `Draw::DrawImage(0x587150)` 逐字绘制，颜色仍走 `Graphics+0x30..3C + colorize`；
- **基线换算**：`Graphics::DrawString` 的 `y` 是**基线**，SysFont 给 `TextOutA`
  的 cell top 是 `y - tmAscent + 1`。所以绘制位置 = `y - ExpGlyphAscent() + 1 + dy`；
  `tmAscent` 直接读**钱币字体对象** `[0x6A7384]+4`（Arial Unicode MS 14pt Bold @96dpi = 19，
  失败兜底 19），这样和原版位置逐像素一致；
- **两遍绘制**：第一遍全部字形的黑色投影 `(+1,+1)`，第二遍正常颜色；先投影后正文，
  避免后一个字的投影盖住前一个字的正文。

产物：

```
pvzclass/pvzdll/assets/expfontcoin14/ExpFontGDI_*.png   (源文件，Arial Unicode MS 14pt Bold)
PlantsVsZombies_CN/images/ExpFontGDI_*.png               (build.bat 自动部署)
```

代码：

- `NativeDrawExpGlyphs()`：设置 `drawMode=NORMAL / colorize=1 / RGBA`，逐字 `DrawImage`；
- `ExpGlyphLoadOnce()`：幂等加载，失败最多重试 4 次（`Draw::ToString` 每次约漏 1KB，不能无限重试）；
- `onDrawExpUIInner()` 的 `Lv.X` / 经验数字改为调用它；
- 字形缺失时自动回退旧的 `NativeDrawExpText()`，保证至少还有字。

这条路径完全不碰 `DrawString` / `Font` / `SysFont` / surface DC / 钱币计数器，
所以颜色和字号只由 PNG 像素与 `Graphics` 字段决定。

### 3.2 停用"强制钱币计数器"hack

`InstallForceCoinBank()` 不再调用（函数保留仅供回溯）。它只是把 DC/DDraw 状态"顺带"
刷成可用，副作用是左下角强制显示钱币数，且对中文字号无效。

### 3.3 升级路线文字

`方案A/B`、`A：极致的输出`、`B：强大的群控` 继续使用已有的 PNG 贴图
（`RouteBtnA/B.png`、`ChooseMelon.png`、`ChooseWinterMelon.png`）——这是中文文本，
走 `SysFont` 就仍然会踩共享 DC 的字号问题。贴图方案是**正确且稳定**的，不是临时绕过。

> 如果以后想让路线文字重新变成代码文本，需要给中文字形做和 3.1 一样的字形图集
> （或者用私有 DIB + GDI 渲染成 Image），不能再直接调 `DrawString`。

## 6. 验证点

1. 关卡内任意植物右下角：`Lv.X` 与经验数字应为**稳定的白/彩色**，不再随钱币数/横幅变化。
2. 西瓜投手达到 3 阶经验后右击：面板、两个方案按钮、两条说明文字应显示正常（贴图）。
3. 若文字完全没出现，检查 `D:\pvz_crash.log` 是否有：
   - `[GLYPH] load try=1 ok=13/13 done=1` → 资源加载成功；
   - `ok=0` → `images\ExpFontGDI_*.png` 没部署（重跑 build.bat 或手动复制）。
4. 若只有 `Lv.` 有字、数字没有：检查数字 PNG 是否被其他 mod 覆盖/删除。

## 7. 回退

- 删除 `PlantsVsZombies_CN/images/ExpFontGDI_*.png`，`NativeDrawExpGlyphs` 会自动回退
  `NativeDrawExpText`（旧的 `DrawString` 路径）。
- 需要完全回到旧行为：把 `onDrawExpUIInner` 里两处 `NativeDrawExpGlyphs` 换回
  `NativeDrawExpText`，并恢复 `InstallForceCoinBank` 调用即可。

## 8. 已知限制

- 字形图只有 ASCII 子集；中文（路线说明）继续用 PNG。未知字符按 8px 空白跳过。
- 字体与阳光/钱币计数一致：**Arial Unicode MS 14pt Bold**（`FONT_CONTINUUMBOLD14`，
  `0x6A7384`；tmAscent=19），不再受 UI 缩放影响；如果以后要随分辨率缩放，需要生成多套
  尺寸或在 `DrawImage` 前设置 Graphics 的缩放字段。
- 如果内测仍觉得偏大/偏小，用 `assets/expfontcoin14/gen_gdi_glyphs.ps1 -PointSize N -Bold`
  重新出图，再同步改 `g_expGlyphDefs` 的 `advance/dx/dy`（脚本会打印这些值）。
  注意：字号必须与 `ExpGlyphAscent()` 读到的钱币字体 tmAscent 匹配，否则基线会偏。
- 投影固定为黑色 `(+1,+1)`；如果换深色背景觉得投影太重，可把 `NativeDrawExpGlyphs`
  里第一遍的颜色/偏移改成 `(0,0,0,180)` / `+1`。
- 字形 PNG 的白色 RGB + alpha 依赖 `DrawImage` 的 `colorize=1`；如果某次改动把 `colorize`
  关掉，文字会显示为白色（不是彩色），但不会变黑/错位。
